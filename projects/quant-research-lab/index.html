Quant Research Lab

Quant Research Lab is an LLM-native research office for equity strategy discovery. The surface looks like a live hacker workspace, but the important part is the loop under it: agents propose ideas, turn them into executable strategy families, backtest them, pass them through statistical gates, remember what worked, and mutate the next research direction.

What the lab is trying to do

The project treats quantitative research as a closed-loop software system. A human does not just ask for one backtest and accept a chart. The lab keeps a research state, generates hypotheses, evaluates them under common failure modes, and feeds the result back into the next proposal. That makes the workflow closer to an experimental operating system than a single notebook.

The core idea is simple: most strategy research fails because the search process is invisible. People try many variations, keep the one chart that looks good, forget the rejected branches, and accidentally overfit to the same historical window. Quant Research Lab makes those invisible choices visible. It records strategy family, parameter lineage, risk checks, benchmark comparisons, transaction-cost assumptions, drawdown behavior, and whether a result added genuinely new signal to the existing alpha pool.

This project is a research simulator and interface experiment. It is not financial advice, not a live trading engine, and not an execution system.

System architecture

The interface is built in React and TypeScript, but the interesting boundary is between the visual office and deterministic research engines. The UI shows analysts, directives, terminal panels, and a boss layer. The engines behind the scene handle strategy generation, simulation, scoring, risk review, and memory updates. That split matters because the visual layer can be playful while the statistical checks stay explicit and inspectable.

The research loop

A typical run begins with a market hypothesis. The lab converts that hypothesis into a strategy family, chooses parameters, runs a historical test, then checks whether the result survives basic scientific pressure. Passing a raw Sharpe ratio is not enough. The lab asks whether the candidate still looks useful after costs, turnover, drawdowns, benchmark comparison, repeated trials, and similarity to strategies already in the pool.

Risk gates instead of pretty curves

The strongest design choice in Quant Research Lab is that the review layer is allowed to reject interesting-looking candidates. It treats the equity curve as evidence, not as proof. The statistical gates are there to fight common research mistakes: multiple testing, strategy crowding, unrealistic costs, overactive turnover, fragile benchmarks, and drawdown profiles that look good only because the sample is friendly.

Deflated Sharpe

Raw Sharpe is adjusted for repeated search. A result that looks strong after many attempts should face a higher bar than the first candidate in a clean experiment.

Alpha overlap

The lab penalizes candidates that are too correlated with the existing pool. New strategies should add signal, not repaint an old exposure.

Trading friction

Costs, turnover, and drawdown gates keep the system from rewarding fragile ideas that only work in a frictionless backtest.

The office as an interface

The anime-office layer is not just decoration. It is a way to make a research process legible while it is running. Analysts can appear busy or blocked, a boss directive can shift the direction of search, and panels can show which engine is acting. The interface makes the loop feel alive, but the important outcome is observability: the user can see whether the system is generating, testing, rejecting, or mutating.

Memory and lineage

Strategy memory is the difference between an agent that merely chats and an agent that researches. Quant Research Lab stores each attempt as part of a family tree. If a momentum idea fails because turnover is too high, the next candidate can respond by changing rebalance frequency, adding a volatility filter, or abandoning the family. If a value signal works but overlaps too much with an existing factor, the lab can search for a cleaner variant.

This structure is also what makes the project useful as a teaching artifact. A reader can inspect why a candidate failed, what the system learned, and how that lesson shaped later proposals. The result is a traceable research notebook with animated state, not just a final leaderboard.

Engineering stack

The current implementation is a front-end research simulator: React 18, TypeScript, Vite, deterministic engines, and testable state transitions. That makes it lightweight enough to run as a site while still keeping the important behavior in code. The project is also organized around files that a future real LLM bridge can call into: strategy generation, risk review, memory, office state, and UI rendering are not collapsed into one visual script.

research_loop = generate_hypothesis
  | compile_strategy
  | run_backtest
  | apply_risk_gates
  | update_memory
  | propose_next_mutation

Why this project matters

The project is interesting because it uses interface design to discipline an AI research workflow. A normal chat agent can produce convincing finance language. Quant Research Lab forces the agent-shaped experience to pass through explicit engines and risk checks. The UI is colorful, but the standard is still programmatic: inputs, tests, state, metrics, rejection reasons, and memory.

That is the right direction for research agents in general. The agent should not only sound smart. It should leave behind evidence, expose uncertainty, remember failed experiments, and make it harder for the user to confuse a clean animation with a valid result.

Roadmap

The README points toward a more serious research allocator: Thompson-sampling direction selection, pool-level delta-Sharpe rewards, MAP-Elites style niche archives, probability-of-backtest-overfitting checks through CSCV, and real bridge adapters for LLM providers. Those additions would move the lab from a convincing simulator toward a controlled autonomous research environment.

Until then, the public version is already valuable as a working prototype of what a quant research agent should look like: entertaining enough to watch, strict enough to reject bad ideas, and structured enough that every result can be traced back through code.
